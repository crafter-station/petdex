# Fork native-platform verification gaps

This file tracks runtime checks that cannot be completed from the fork's Windows development machine. It is intentionally unlinked and is not a substitute for shared tests or platform CI. Confirmed regressions must be fixed in code.

| Platform / environment | Feature | Expected behavior | Reproduction | Status |
| --- | --- | --- | --- | --- |
| macOS 26+, Apple Silicon | Liquid Glass cards | Native cards use the system material, remain attached during pet drag/throw, and preserve all/recent/hidden, one-card, pin, dismiss, and nested-subagent behavior. | Start two mixed-agent sessions, expand a nested child, cycle disclosure modes, drag and throw the pet, then toggle Light/Dark and Reduce Motion. | Shared Zig coverage passes; native runtime recheck needed. |
| macOS 15+, Apple Silicon | VoiceOver | Every card and dynamic action has an accurate name; actions are exposed only when eligible and activate without bringing the activity panel itself forward. | Enable VoiceOver, navigate the activity cards and invoke Open, Pin, Subagents, Dismiss, and disclosure where present. | Native runtime recheck needed. |
| Linux, Wayland (GNOME and KDE) | Focus activation and accessibility | Open is hidden when the compositor cannot verifiably activate the recorded application; browser Open remains hidden until registered-default resolution exists. GTK-native controls expose every eligible action to keyboard/AT without intercepting pointer input before the portable rail is visible. Eligibility changes and card reordering must not leave a stale role, checked state, label, or command. | Run sessions from a native terminal and VS Code under each compositor; add a browser-origin event; then transition one card through Pin-only, child/Subagents, completed/Dismiss, removal, and reorder states while traversing/invoking GTK controls with Orca or Accerciser. Preserve `*-gtk-eligibility.mp4` and `*-gtk-transitions.txt`. | Headless Weston proves unsupported Open absence and bounded accessibility metadata. The GTK bridge has static/shared-model and cross-compile coverage; real Orca/Accerciser action/state verification and compositor-specific positive activation remain manual. |
| Linux, Wayland (GNOME and KDE) | Popup stacking and movement | Portable cards remain above the pet, gaps remain click-through, and the popup tracks native compositor dragging without lag or offset drift. | Display multiple cards across two monitors, drag the pet across the monitor boundary, release, and repeat with fractional scaling. | Headless Weston CI proves individually asserted popup-local disclosure transitions and card-local gesture delivery without global coordinates. The SDK exposes no movement oracle, so actual movement, GNOME/KWin stacking, input-region gap hit-testing, and multi-monitor placement remain manual. |
| Linux, X11 | Interaction/performance smoke | Disclosure modes render and transition correctly at scale 1/2, nested rows stay bounded, and active updates do not cause persistent redraw while idle. | Windows 10/11 | Native bubble visual and accessibility matrix | DWM and software fallbacks render readable cards; High Contrast and 200% scaling preserve layout and controls. | Follow the Windows matrix in `native-platform-verification.md` on physical or nested-desktop runners. | CI compares baseline and bubble screenshots at all four outside-corner pixels and the painted center, enumerates native UIA fragments, and cycles the disclosure without foreground focus theft. When verifying a row, record the exact OS/compositor version, display scaling and monitor arrangement, attach screenshots or accessibility output where useful, and replace the status with the result and follow-up issue if one is needed.
